# Architecture Overview

The `snake_game` is designed using a monolithic modular structure in Rust.

- **Entry Point:** `src/main.rs` initializes the game state, parses CLI arguments (such as `--bot` or `--spectator`), and runs the main event loop.
- **Library Root:** `src/lib.rs` exports all internal modules.
- **Game Engine:** `src/game/` handles all logic related to state progression, scoring, pathfinding, and interactions.
- **UI & Rendering:** `src/ui.rs` manages drawing elements on the terminal via the `crossterm` crate.
- **Wall handling:** `calculate_final_heads`/`get_final_p` treat out-of-bounds cells as lethal walls (or wrap them when `wrap_mode` is on); in Ricochet mode a player wall hit is instead reflected by `ricochet_bounce` (see [Ricochet Mode](../mechanics/README.md#ricochet-mode)).

## Autopilot Safety Pipeline

The autopilot (`Game::calculate_autopilot_move`, `calculate_p2_autopilot_move`, and the arena-bot branch of `handle_autopilot_moves` in `src/game/game_struct.rs`, which covers the arena bots of MassiveMultiplayer, Tron, Zombie, King of the Hill, and Turf War) decides every bot move through a layered pipeline. In `GameMode::Tournament` both match entrants (the player snake and `player2`) are driven by this same pipeline, including the Hunter AI layer, so tournament matches are full verified-safe bot duels.

1. **Target selection:** food, bonus food, power-ups, goblins, merchants, and mode-specific objectives (KoTH zone, CTF flags, dungeon doors/bosses, crops, and in Turf War the nearest frontier turf cells via `turf_war_frontier_targets`). Targets are filtered for contention first (`contested_targets`): a target is contested when a rival snake is predicted to reach it strictly earlier than the bot, either by wrap/portal-aware travel distance (`travel_dist`) or because the rival's committed head path crosses it sooner; contested targets are only tried when no uncontested target verifies (`astar_search_verified_contested`). Targets on a rival's current head (Zombie-style hunt targets) are never contested, and the filter is inert in single-player or while invincible.
1a. **Hunter AI (`hunting_move`):** in rival modes, when the mover is strictly longer than a nearby rival, the bot projects every shorter rival's committed head path up to `CUTOFF_HORIZON` (12) steps (`cutoff_targets`) and looks for a path onto a rival's predicted head cell one step before the rival arrives, so the rival crashes into the mover's body. Kill candidates pass the full safety pipeline below plus `path_cuts_off_rival`, which replays the path against each rival's predicted head path using the engine's pre-move-body collision rule (the mover's tail cell does not count, since it vacates in time); the shortest verified kill is taken. Flag carriers in CTF never hunt.
2. **A\* search (`astar_search`):** heuristic penalties for hazards and enemy bodies, dynamic edge costs for lasers/mines/turrets/black holes/lightning/meteors, plus trap-aware tail-reachability validation (`path_keeps_tail_reachable`) so candidate paths that would seal the mover into a dead end are rejected during the search. In Battle Royale the shrinking safe zone is a hard constraint too: `astar_search` never expands into a cell outside `within_safe_zone(cell, arrival_step)` — even for target cells. Drifting meteors (`Meteor::vx != 0`, Asteroids showers) are predicted exactly: `meteor_position_after`/`bounced_x` simulate the bounce-and-fall trajectory, and the predicted lanes are penalized in the heuristic (`meteor_lane_penalty`), the edge costs (`meteor_edge_cost`, also in `get_boss_path`), and the trap-check blocked set (`trap_blocked_cells`).
3. **Verified-safe selection (`astar_search_verified` + `path_is_safe`, driven by `astar_search_verified_contested` for objective targets):** every candidate path is replayed step-by-step; each cell is re-checked with `is_safe_final_p` at its true arrival step. `is_safe_final_p` first enforces the safe-zone border via `within_safe_zone`, with the margin projected to that step by `zone_margin_at` (which assumes the 500 ms maximum tick `MAX_TICK_DURATION`, so the projected shrink is conservative), matching the engine's wall/zone rule even while invincible. For drifting meteors (`Meteor::vx != 0`), `is_safe_final_p` calls `meteor_would_hit`, which computes the exact tick(s) at which the meteor reaches the cell's row and checks the bounced column, so a cell on a drifting meteor's trajectory is a hard constraint at the step the meteor arrives; `path_is_safe` additionally rejects paths where a drifting meteor sweeps into a cell the snake's body still occupies. Rival snakes are predicted two ways: `rival_head_lane_mask` projects each rival's head straight ahead for `RIVAL_HEAD_HORIZON` steps (and the A* expansion avoids those lanes), while `predicted_enemy_occupancy` simulates every other snake forward along its committed direction queue so predicted enemy head/body occupancy at each step is a hard constraint. Among all verified paths, the one leaving the most reachable free space after arrival (`reachable_space_after_path`, minus path length) is kept; its flood fill is zone-aware as well, so only cells inside the projected zone count as survivable space. The telegraphed impact cell of each falling meteor is reported by `meteor_impact_cells` and rendered as a warning marker in both UIs.

4. **Survival fallbacks:** tail-chasing (`astar_search_verified` toward the snake's own tail), then `flood_fill_fallback`, which picks the first step maximizing reachable open space.

In **Conveyor mode** (`GameMode::Conveyor`) the belt shove is applied inside `calculate_final_heads` (and in the arena-bot head loop) right after portal/wrap resolution: `belt_shove` only returns a destination that is in bounds (or wrapped), free of obstacles, snake bodies, portals, mines, bosses, turrets, lasers, meteors, the black hole, the tornado vortex, the lightning column, wildfire, and the projected safe zone — so a shove always lands on a verified-safe cell and the autopilot survives natively by re-planning from its actual head each tick.

In **Meteor Shower mode** (`GameMode::MeteorShower`) the scheduled strikes always pick a fair column (`pick_safe_strike_column`: no snake head/body column and no column a snake is about to enter), and the meteor-column hazard checks above are what let the bot survive the bombardment natively.

In **Landslide mode** (`GameMode::Landslide`) the horizontal analog of the meteor hazard is handled the same way: `rock_position_after` predicts each rolling rock's cell `steps` ticks ahead, `rock_would_hit` is a hard constraint in `is_safe_final_p`, `path_is_safe` rejects paths whose predicted rock lane sweeps a still-occupied body cell, and `rock_lane_penalty`/`rock_edge_cost` penalize the rock's row in the A* heuristic and edge costs (in both A* implementations), so the bot rides out the landslide natively.

In **Quicksand mode** (`GameMode::Quicksand`) the walkable-but-sinking bog (`quicksand`) is treated as a hard-blocked terrain by the autopilot: every bog cell fails `is_safe_final_p`, so the A* expansion never enters it, `path_is_safe` rejects paths through it, and `trap_blocked_cells` marks all bog cells blocked in the trap-avoidance flood fill. The bog itself can never claim a snake: `is_quicksand_cell_blocked` refuses snake bodies, the cells snakes are about to enter, entities, and hazard tiles, so a head only sinks when it lingers in the bog for `QUICKSAND_SINK_TICKS` ticks.
In **Gale mode** (`GameMode::Gale`) the wind gust is applied in `update` right after the `belt_shove`/`tramp_launch` steps for the arena-bot head loop and for the player/player-2 final heads: `gale_shove` only returns a destination that is in bounds, passes `tramp_cell_free` (snake bodies, next-heads, obstacles, mines, entities, lethal tiles), lies outside every falling meteor's lane (`gale_meteor_lane`), and is not in `gale_claimed` (seeded from `singularity_next_heads` and extended with every final head this tick) — so a gust always lands on a verified-safe, unclaimed cell, a braced player (`gale_braces > 0`) is never pushed, and the autopilot survives natively by re-planning from its actual head each tick.

In **Tar Pit mode** (`GameMode::TarPit`) the spreading tar pits are mirrored into `obstacles` on activation, so tar cells are ordinary hard obstacles in `is_safe_final_p`, `path_is_safe`, and both A* implementations — the bot routes around the tar natively. Fairness lives in `is_tar_cell_blocked` (never the border ring, a snake's body, the cell any snake is about to enter, or any entity — re-checked at activation via `phase_next_cells`), the telegraph in `tar_warnings` makes every claim visible 3 ticks ahead, and the setting cycle at tick 200 of every 250-tick cycle plus the food stomp keep the pits from sealing the board.
In **Faultline mode** (`GameMode::Faultline`) the collapsing floor needs no prediction: collapsed pits live in `obstacles`, so they are already hard constraints in the A* search, `is_safe_final_p`, and the `trap_blocked_cells` flood fill, and the still-telegraphing cracks (`fault_tiles`) are added to the same `is_safe_final_p` and `trap_blocked_cells` wall sets, so the bot simply never routes onto cracking floor — and since `fault_collapse_blocked` defers any collapse onto a snake's body or next-head cell, the floor can never collapse under the bot either.


## Persistence / Save Format

`SaveState` (`src/game/save_state.rs`) is serialized to JSON by `save_game`/`save_game_to_file` and read back by `load_game_from_file`; `HistoryState` mirrors the same fields for time-rewind. Maps whose keys are not strings (e.g. `painted_tiles: HashMap<Point, u8>`, `eggs_on_board: HashMap<Point, EggType>`, `dungeon_grid: HashMap<(i32, i32), DungeonRoom>`, `blaze_tiles: HashMap<Point, u32>`, `blaze_tiles: HashMap<Point, u32>`) cannot be JSON objects, so they are serialized through the `map_as_pairs` helper (`src/game/map_as_pairs.rs`) as JSON arrays of `[key, value]` pairs. Deserialization accepts both that pair form and the legacy empty-object form written by older versions, so existing save files keep loading. Covered by [tests/test_save_integrity.rs](../../tests/test_save_integrity.rs).
