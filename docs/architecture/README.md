# Architecture Overview

The `snake_game` is designed using a monolithic modular structure in Rust.

- **Entry Point:** `src/main.rs` initializes the game state, parses CLI arguments (such as `--bot` or `--spectator`), and runs the main event loop.
- **Library Root:** `src/lib.rs` exports all internal modules.
- **Game Engine:** `src/game/` handles all logic related to state progression, scoring, pathfinding, and interactions.
- **UI & Rendering:** `src/ui.rs` manages drawing elements on the terminal via the `crossterm` crate.

## Autopilot Safety Pipeline

The autopilot (`Game::calculate_autopilot_move`, `calculate_p2_autopilot_move`, and the arena-bot branch of `handle_autopilot_moves` in `src/game/game_struct.rs`, which covers the arena bots of MassiveMultiplayer, Tron, Zombie, King of the Hill, and Turf War) decides every bot move through a layered pipeline. In `GameMode::Tournament` both match entrants (the player snake and `player2`) are driven by this same pipeline, including the Hunter AI layer, so tournament matches are full verified-safe bot duels.

1. **Target selection:** food, bonus food, power-ups, goblins, merchants, and mode-specific objectives (KoTH zone, CTF flags, dungeon doors/bosses, crops, and in Turf War the nearest frontier turf cells via `turf_war_frontier_targets`). Targets are filtered for contention first (`contested_targets`): a target is contested when a rival snake is predicted to reach it strictly earlier than the bot, either by wrap/portal-aware travel distance (`travel_dist`) or because the rival's committed head path crosses it sooner; contested targets are only tried when no uncontested target verifies (`astar_search_verified_contested`). Targets on a rival's current head (Zombie-style hunt targets) are never contested, and the filter is inert in single-player or while invincible.
1a. **Hunter AI (`hunting_move`):** in rival modes, when the mover is strictly longer than a nearby rival, the bot projects every shorter rival's committed head path up to `CUTOFF_HORIZON` (12) steps (`cutoff_targets`) and looks for a path onto a rival's predicted head cell one step before the rival arrives, so the rival crashes into the mover's body. Kill candidates pass the full safety pipeline below plus `path_cuts_off_rival`, which replays the path against each rival's predicted head path using the engine's pre-move-body collision rule (the mover's tail cell does not count, since it vacates in time); the shortest verified kill is taken. Flag carriers in CTF never hunt.
2. **A\* search (`astar_search`):** heuristic penalties for hazards and enemy bodies, dynamic edge costs for lasers/mines/turrets/black holes/lightning/meteors, plus trap-aware tail-reachability validation (`path_keeps_tail_reachable`) so candidate paths that would seal the mover into a dead end are rejected during the search. Drifting meteors (`Meteor::vx != 0`, Asteroids showers) are predicted exactly: `meteor_position_after`/`bounced_x` simulate the bounce-and-fall trajectory, and the predicted lanes are penalized in the heuristic (`meteor_lane_penalty`), the edge costs (`meteor_edge_cost`, also in `get_boss_path`), and the trap-check blocked set (`trap_blocked_cells`).
3. **Verified-safe selection (`astar_search_verified` + `path_is_safe`, driven by `astar_search_verified_contested` for objective targets):** every candidate path is replayed step-by-step; each cell is re-checked with `is_safe_final_p` at its true arrival step. For drifting meteors (`Meteor::vx != 0`), `is_safe_final_p` calls `meteor_would_hit`, which computes the exact tick(s) at which the meteor reaches the cell's row and checks the bounced column, so a cell on a drifting meteor's trajectory is a hard constraint at the step the meteor arrives; `path_is_safe` additionally rejects paths where a drifting meteor sweeps into a cell the snake's body still occupies. Rival snakes are predicted two ways: `rival_head_lane_mask` projects each rival's head straight ahead for `RIVAL_HEAD_HORIZON` steps (and the A* expansion avoids those lanes), while `predicted_enemy_occupancy` simulates every other snake forward along its committed direction queue so predicted enemy head/body occupancy at each step is a hard constraint. Among all verified paths, the one leaving the most reachable free space after arrival (`reachable_space_after_path`, minus path length) is kept.
4. **Survival fallbacks:** tail-chasing (`astar_search_verified` toward the snake's own tail), then `flood_fill_fallback`, which picks the first step maximizing reachable open space.

In **Meteor Shower mode** (`GameMode::MeteorShower`) the scheduled strikes always pick a fair column (`pick_safe_strike_column`: no snake head/body column and no column a snake is about to enter), and the meteor-column hazard checks above are what let the bot survive the bombardment natively.

## Persistence / Save Format

`SaveState` (`src/game/save_state.rs`) is serialized to JSON by `save_game`/`save_game_to_file` and read back by `load_game_from_file`; `HistoryState` mirrors the same fields for time-rewind. Maps whose keys are not strings (e.g. `painted_tiles: HashMap<Point, u8>`, `eggs_on_board: HashMap<Point, EggType>`, `dungeon_grid: HashMap<(i32, i32), DungeonRoom>`) cannot be JSON objects, so they are serialized through the `map_as_pairs` helper (`src/game/map_as_pairs.rs`) as JSON arrays of `[key, value]` pairs. Deserialization accepts both that pair form and the legacy empty-object form written by older versions, so existing save files keep loading. Covered by [tests/test_save_integrity.rs](../../tests/test_save_integrity.rs).
